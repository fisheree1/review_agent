# 学习 Agent 工作流开发设计

日期：2026-09-27。状态：组合学习主流程已实现，LangGraph 承担问答与出题的证据工具编排；生产默认关闭，等待实际资料质量及成本验收后开启。本文件细化 [框架接入规划](./langgraph-integration-plan.md)，作为后续功能设计、开发拆分与验收依据。

## 1. 用户目标与开发范围

用户在一个对话框内说明学习目标，系统选择允许的工具完成任务，并展示依据、结果和需要用户参与的步骤。第一条完整场景为：

> 根据这两份资料总结第三章，再生成 5 道中等难度单选题。我做完后帮我解释错题，再练习薄弱点。

用户不需要了解模型、图节点或工具参数。任务步骤必须可理解，资料范围必须明确，已有成果必须可找回。

| 能力 | 当前基线 | 本轮设计目标 |
| --- | --- | --- |
| 对话入口 | `/study` 统一输入问题与学习任务 | 沿用入口，增加组合任务卡片 |
| 受控执行 | 单项问答、总结/比较、Quiz、实际错题复习及薄弱点练习 | 显式图节点、条件分支、有界工具选择 |
| 作答 | 对话内与独立页面共享练习、提交、成绩组件 | 绑定任务作答记录，跨页面继续 |
| 等待与恢复 | 未提供跨交互组合工作流 | 等待提交时释放 Worker，刷新或重启后恢复 |
| 过程展示 | 消息排队/处理中及最终结果 | 计划、阶段、等待原因、已完成成果 |
| 数据安全 | 正式认证、workspace 限域、来源校验、任务租约 | 覆盖运行、检查点、恢复与删除的新访问路径 |

本次文档不扩大到任意代码执行、公开网络搜索、自动提醒、团队共享或正式考试。每份 Quiz 仍遵守当前 1–10 题的产品约束。

## 2. 设计决策

1. **LangGraph 负责执行编排。** 应用代码持有权限、预算、业务状态、来源校验与结果发布；领域和应用端口不依赖图 SDK。
2. **按需接入 LangChain。** M1 使用现有模型适配器，M2 单独评估模型/消息组件，降低同时改变编排和供应商协议的风险。
3. **PostgreSQL 保存事实。** 消息、Quiz、作答和评分是业务事实；检查点记录执行位置及有限中间状态。Redis 沿用限流用途，不增加第二套任务事实源。
4. **用户请求授权明确的学习步骤。** 普通问答和出题不反复确认；缺少关键参数时才澄清。模型无法授权删除、分享或覆盖记录。
5. **一条运行固定资料与版本。** 新问题使用当前选择范围，旧任务保留创建时的范围。模型不得改变 workspace、文档集合或执行引擎版本。
6. **先交付顺序流程。** 不同时引入多 Agent、并行研究和复杂子任务调度。只有评测证明收益时再扩大执行方式。

框架选择、候选依赖及官方依据见 [接入规划](./langgraph-integration-plan.md)。产品与 UI 的当前事实仍以 [产品需求](./product-requirements.md) 和 [UI 规范](./ui-design-system.md) 为准；启用新行为的代码变更必须同步更新这些基线。

## 3. 真实用户旅程

### 3.1 发起学习任务

- 输入框始终显示资料范围；示例按钮仅填入可编辑草稿，不直接发起付费任务。
- 发送后展示简短计划：“总结第三章 → 生成练习 → 等待你作答 → 解释错题 → 薄弱点练习”。执行前展示不等于额外确认门槛。
- 缺少章节或题型等影响结果的参数时，在原对话内提问；补充内容与原运行关联，不生成另一条重复任务。
- 用户可在发送前修改要求。执行开始后的改题量、改章节或改范围，停止剩余步骤并创建新运行，保留原记录，不覆盖已完成成果。

### 3.2 获取总结与练习

- 总结经引用校验后即可展示，不等待整条学习流程结束。
- 练习卡显示实际题量、题型和难度；证据只支持 2 道合格题时显示“已生成 2 / 5 题，现有资料不足以支持其余题目”。遵循现有发布规则，不用不合格题补齐数量。
- 证据不足时提供可执行入口：“查看来源”“补充资料后新建任务”；不把无来源的推测作为学习结论。
- 作答前隐藏正确答案、解析和题目证据入口，避免提前泄露答案；章节总结的引用正常可见。

### 3.3 等待作答与继续提问

- 等待卡显示“练习已准备好，完成并提交后继续解释错题”，主按钮为“继续作答”。可离开页面。
- **等待作答不禁用对话输入框。** 用户可以问“刚才的概念是什么意思”，也可以切换资料提新问题。
- 初期每个对话最多一条正在执行模型步骤的运行；等待中的运行不占执行名额。新的付费任务进入明确队列，不能覆盖原等待任务。
- 首次绑定到运行的作答记录是后续复习依据。同一 Quiz 的其他重做记录不会自动替换；用户要求复习另一份记录时走新的请求。
- 提交被接受不等于评分完成。含简答题时显示“已提交，正在评分”；评分完成且作答进入已提交状态后，才以真实成绩推进复习。

### 3.4 成绩、错题与薄弱点

- 分开展示得分、错误原因、解释与来源；简答题模型评分保留“模型提示”标记，不暗示人工确认。
- 薄弱点依据本次实际提交记录；没有错题或可识别薄弱点时结束任务，显示“本次练习未发现需要复习的薄弱点”。
- 用户可以主动再练一次，系统不为完成计划而编造弱点或创建额外题集。
- 点击来源后能回到原作答位置；结果在对话内和独立练习页使用同一业务资源与组件。

### 3.5 范围、刷新与中断

| 用户情况 | 界面行为 | 后端约束 |
| --- | --- | --- |
| 切换当前资料 | 输入区显示新范围；旧任务标注原范围 | 新范围只作用于新请求 |
| 原资料版本变化 | 显示“资料已更新，请使用新版本重新开始” | 旧运行禁止静默换版本恢复 |
| 来源被删除 | 相关成果按现有删除政策失效/清理 | 立即撤销访问，传播删除至检查点与产物 |
| 刷新或离开页面 | 从服务器加载阶段、成果与作答记录 | 不依赖浏览器内存维持任务 |
| 网络断开 | 显示“连接中断，任务可能仍在继续” | 重连查询状态，不自动重新发送任务 |
| 用户停止 | 显示“已停止后续步骤”及已完成入口 | 保留合规的已发布成果，阻止晚到结果发布 |
| 服务重启 | 对账已完成阶段，继续可安全执行的步骤 | 租约、幂等键与累计预算保持有效 |
| 模型请求结果未知 | 显示“当前步骤未确认完成，请查看已完成内容” | 标为需处理，不自动重发同一付费调用 |

取消与资料删除语义不同：取消保留既有成果；删除仍执行既有资料清理规则，不能用“保留成果”绕过删除。

## 4. 界面与交互规范

沿用现有颜色、字体、圆角、边框、间距与明暗主题 Token。复用 `QuizAttemptPanel`、来源面板和错误组件；任务卡只增加阶段展示，不建立第二套练习 UI。

建议的信息顺序：

```text
学习任务 · 第三章                   原范围：讲义 A、讲义 B
✓ 章节总结     ✓ 练习     ● 等待你作答     ○ 错题复习
已生成 5 道中等难度单选题
[继续作答]  [查看总结]  [停止后续步骤]
```

- 每个阶段只有一个主要操作；已完成结果可展开，默认不铺满多份练习。
- 执行时显示真实阶段与实际完成数量，不展示虚构百分比或无法保证的预计时间。
- 用户阅读历史消息时，新结果不强制滚动到底部；提供“查看新结果”。新状态不抢走输入焦点。
- 控制按钮、单选组和题目定位 ID 在多处展示同一资源时仍唯一。390px 单栏布局不横向溢出，触控入口建议至少 44px。
- Ctrl/Command + Enter 发送，中文输入合成期间不触发；状态用短文本区域播报，避免重新播报整段历史。错误不能只通过短暂提示显示。
- 作答草稿计划增加服务端自动保存：串行提交、返回修订号，过期写入拒绝；只有服务器确认后显示“已保存”。离开前未完成保存时明确提示，重新打开加载服务端草稿。
- 草稿自动保存和并发修订保护属于待开发能力，当前接口不能直接被描述为已经提供该保证。默认不把私有答案或资料内容长期放在浏览器本地存储。

## 5. 运行与阶段状态

以下为拟新增状态，不替换当前消息的 `queued / processing / answered / insufficient / failed / cancelled`。

| 运行状态 | 含义 | 下一步 |
| --- | --- | --- |
| `queued` | 等待可用 Worker 或恢复事件 | 领取后进入 `running` |
| `running` | 正在执行允许的阶段 | 完成、等待、阻塞或失败 |
| `waiting_input` | 等待澄清或用户作答 | 合法输入/提交事件后排队 |
| `waiting_result` | 用户已提交，等待独立评分任务完成 | 合法评分完成事件后排队；不占 Worker |
| `blocked` | 结果未知、版本不兼容等需处理状态 | 仅允许经过用例校验的处理，或终止 |
| `completed` | 必要步骤均已完成，或薄弱点步骤合理跳过 | 终态 |
| `failed` | 不可恢复错误或有界重试耗尽 | 终态；新建任务沿用已有成果引用 |
| `cancelled` | 用户停止或系统按授权规则终止 | 终态 |
| `expired` | 等待期限已过 | 终态；已有业务记录依保留政策处理 |

阶段采用 `pending / running / waiting / completed / skipped / blocked / failed / cancelled`。等待阶段记录具体原因，区分用户输入与后台评分；评分失败关联现有失败记录与有界处理策略，不能误当作用户未作答。运行终态不再接受恢复；阶段跳过必须有确定性原因。等待期限做配置，M3 前确定默认值及提前提示政策，不能在实现前承诺无限等待。

消息结果与运行生命周期分开：总结消息可以已回答，而关联运行仍等待作答。前端不能用“消息已回答”推断整个流程结束，也不能重复保存另一份成绩。

### 执行路径

```text
鉴权与范围快照 → 结构化规划 → 计划校验
  → 总结子图：规划证据 → 搜索/读取 → 生成 → 引用校验 → 发布
  → Quiz 子图：蓝图 → 检索 → 候选生成 → 校验 → 发布
  → 纯等待节点：绑定 attempt → 持久化等待 → 释放 Worker
  → 实际评分完成事件 → 复习已提交记录
  → 有薄弱点：生成针对性 Quiz；无薄弱点：跳过并完成
```

允许计划必须由版本化 schema 表达。第一版只允许上述模板及现有单项任务，不允许模型创建任意节点或递归嵌套工作流。搜索/读取通过条件边选择，次数和证据量受预算控制。

## 6. 接口契约与前后端协作

以下接口为拟开发契约；实现时同步 OpenAPI、前端类型和兼容性测试。

| 接口 | 职责与限制 |
| --- | --- |
| 现有 `POST /api/v1/conversations/{id}/messages` | 保留 `question` 与 Idempotency-Key；异步创建消息，按功能开关关联运行 |
| `GET /api/v1/conversations/{id}/agent-runs` | 游标分页返回所属对话的运行摘要，支持刷新找回 |
| `GET /api/v1/agent-runs/{run_id}` | 返回公开投影：状态、范围、步骤、等待原因、成果引用和修订号 |
| `POST /api/v1/agent-runs/{run_id}:respond` | 接收澄清答案与预期修订号；服务器验证当前等待类型和幂等键 |
| `POST /api/v1/agent-runs/{run_id}:cancel` | 幂等停止剩余步骤，增加取消代次并阻止晚到发布 |
| 现有 Quiz 作答/提交接口 | 保存与提交真实答案；评分完成后产生内部推进事件 |

客户端不提供 workspace、检查点 thread、图状态、工具调用、Prompt、租约或任意 `goto/resume` 命令。`run_id` 是定位信息，不是授权凭据。作答提交仍经过已有业务授权，不由客户端直接发图恢复指令。

新消息增加可选 `run_id`；运行投影引用现有消息、Quiz 和 attempt，不复制完整答案。先支持前端未知字段/结果类型，再启用新后端契约；不要直接扩大 `task_result.kind` 而使旧界面失去渲染能力。

建议稳定错误契约：跨空间/不存在资源返回 404；非法参数返回 422；旧修订、已关闭运行或来源版本冲突返回 409；配额耗尽返回 429；暂时不可用返回 503。错误码分别区分 `RUN_REVISION_CONFLICT`、`RUN_CLOSED`、`RUN_SOURCE_CHANGED`、`RUN_BUDGET_EXCEEDED` 等原因，并提供对应文案；不返回供应商响应或检查点内容。

第一版通过现有轮询节奏查询业务投影；终态停止轮询，页面隐藏时降低频率。SSE 是后续优化，需服务器授权、持久事件游标与重连补偿，不能直接向浏览器转发 Worker 原始图事件。

## 8. 持久化、恢复与费用安全

### 8.1 拟新增数据

- `agent_runs`：workspace、对话/触发消息、引擎/图/计划版本、固定资料版本、状态、阶段、修订号、累计预算、租约/取消代次、等待类型与到期时间。
- `agent_stage_executions`：运行/阶段/尝试标识、幂等键、调用状态、执行时间、用量、稳定错误码和成果引用。
- 检查点：保存执行位置、证据 ID、输出引用和必要计量；私有中间产物有明确归属和保留期。
- 内部事件：评分完成及清理等需可靠交付的事件，与对应业务变更同事务写入；重复投递最多推进一次。

查询字段使用显式列，变动的计划结构才使用 JSONB。运行、阶段、文档版本、Quiz、attempt 的所有权使用复合外键或等效数据库约束。检查点 schema 经 Alembic/受审计迁移步骤管理，运行角色不能执行框架建表流程。

### 8.2 一次执行的事务边界

1. 短事务领取阶段，记录租约与预算预留，随后提交。
2. 事务外加载经授权的证据、执行模型调用；每个边界检查取消及预算。
3. 保存可恢复的调用结果与实际用量，验证来源/答案。
4. 短事务核对租约代次和状态，以阶段幂等键原子发布业务成果。
5. 更新检查点；若此时崩溃，重投读取已发布成果并补齐执行位置。

业务提交与检查点不是天然同一事务。阶段执行记录负责对账，不能靠重跑整个节点解决不一致。等待节点不得包含出题/发布等副作用，避免恢复时节点重新执行造成重复。

Quiz 发布、运行成果关联与等待关联应在同一业务事务中形成一致记录；作答创建时绑定运行。注册等待和处理评分事件都读取实际 attempt 状态，已完成评分的记录立即满足等待条件，避免用户提交很快、事件先于图进入等待时永久卡住。失败事件可重复消费但不得覆盖已经完成的阶段。

外部调用结果未知时禁止盲目自动重发。已取得且合法保存的结果可以继续验证与发布；尚未发送的调用可以按明确错误分类有界重试。检查点不能保证供应商只收费一次。

### 8.3 全流程预算

当前单任务边界作为迁移基线：最多 7 次模型调用、5 次证据规划、2 次搜索、3 次读取、18,000 Token、30,000 相对成本单位和 110 秒执行时间；相对成本单位不等于实际货币价格。

组合运行额外限制总阶段数、题集数、模型调用、Token、费用与累计执行时长，M0 用真实基线确定配置，M4 开启前必须有明确上限。等待用户不占 Worker 执行超时，但有独立等待期限。恢复、模型适配器内部重试与子图执行不能重置预算。

简答评分使用现有评分任务，若属于组合运行，其模型用量也计入对应运行并预留额度；现有评分端口若没有完整用量返回，先扩展契约，不能把独立评分调用排除在总预算外。普通单项任务配额继续生效。

### 8.4 删除与权限传播

- 每次读取、恢复、发布和清理验证 workspace、范围及运行状态；检索过滤必须在正文进入模型前完成。
- 来源删除立即使对应运行不可访问/不可恢复，随后可靠清理检查点、中间产物与衍生记录。
- 级联删除前同事务保存独立清理意图，不能让父记录删除同时删掉尚未执行的清理任务。
- 日志仅记录稳定 ID、阶段、时间、计量与脱敏错误码，不记录正文、Prompt、答案或令牌。
- 明确备份保留政策与恢复后的删除重放。LangSmith 等额外数据外发默认关闭。

## 9. 开发顺序与交付物

每阶段按“确认契约 → 最小实现 → 风险测试 → 文档更新 → 评审”推进。保持小提交，代码涉及的 PRD、API、schema、UI 和运维决策一起更新。普通测试用假模型，真实付费评测单独执行并记录范围。

部署采用扩展迁移与功能开关：先发布兼容 schema 和消费者，再发布兼容前端，最后启用入口。图任务启用前必须确认旧 Worker 已退出或不会领取新引擎任务；仅在新代码里加筛选不足以约束仍运行的旧消费者。

运行固定引擎/图版本；关闭新入口只影响新运行。旧等待运行由兼容 Worker 完成或明确终止，不强行交给旧执行器。生产回退保留兼容字段，不用破坏性 downgrade 丢弃任务或成绩。

## 12. 本次交付与设计调整

### 已实现

- `StateGraph` 显式运行规划、搜索、读取、生成及校验节点；应用层通过 `StudyExecutor` 端口调用，领域规则不依赖框架。独立 Worker 执行模型调用。
- 对话支持单次问答、出题、复习、薄弱点练习及明确要求的组合学习任务。例如：“先总结中位数与均值，出 3 道单选题；提交后分析错题，并给薄弱点练习”。规划采用严格 schema，不自动添加用户未请求的复习步骤。
- `0014_agent_workflows` 增加 workspace 所属运行及阶段调用回执；固定资料范围和版本，消息含 `run_id`。等待作答时释放执行资源，允许继续提问及切换后续提问范围；旧任务保持发送时范围。
- 总结引用先校验再显示；Quiz 保留请求题量和实际通过题量；提交前隐藏答案、解析及来源。组合任务绑定唯一真实 attempt，评分完成后再生成错题回顾；最多一次薄弱点题集，避免递归循环。
- 澄清提交采用幂等键及修订号，仅允许一次补充重规划；再次需要澄清则结束。刷新从服务端恢复，不重新创建任务。取消保留已完成成果并停止后续步骤。
- 作答 550ms 自动保存，串行请求携带 `expected_revision`，提交前等待保存。服务器已保存但响应丢失时可重放相同值；不同值的陈旧修订被拒绝。本页保留失败草稿，提供重试或明确放弃未保存修改并加载服务器记录。
- 任务卡复用现有设计 Token 和 Quiz 作答组件；窄屏按步骤显示总结、练习、成绩、薄弱点练习；不显示 Prompt、工具原始载荷或未校验答案。

### 持久化决策

遵循 [ADR-0002](./adr/0002-agent-business-checkpoints.md)：未启用框架原生 `AsyncPostgresSaver`、`interrupt()` 或 LangSmith 托管追踪；等待与恢复由 PostgreSQL 业务运行记录负责。证据图在阶段内执行，重启重放已经返回的调用回执；未知调用结果进入 `blocked`，禁止自动再次付费。评分和运行恢复在同一事务完成，不增加独立 Outbox 队列。LangChain 模型组件留作供应商变化时评估，当前沿用已有 HTTPX 适配器。

阶段发布与运行位置更新同事务提交，替代原设计第 8.2 节的独立检查点补写。调用回执为私有短期 JSONB，阶段发布即清空，取消/已知失败/到期删除或清空；删除源资料版本级联删除关联运行及回执。未知结果保留稳定状态供检查，不向浏览器暴露回执。

### 生效上限

单个证据阶段最多 5 次决策、2 次搜索、3 次读取、7 次模型调用、18,000 Token 和 30,000 相对费用单位。整个运行累计最多 22 次模型调用、8 次查询 Embedding、54,000 Token、90,000 相对费用单位及 770 秒预留执行时间；每次领取预留 110 秒，恢复不重置。实际执行秒数单独记录。每阶段最多 12 个调用回执。全运行期限默认 7 天（`AGENT_WAIT_DAYS`，1–30），到期由 Worker 关闭。费用单位不是人民币或供应商报价。

### 本次验证结果（2026-09-27）

后端 111 项测试、前端 20 项组件测试及构建、5 条移动端/既有对话/认证/引用浏览器回归通过；原 PDF 上传实测因未提供测试文件跳过，该路径本次未修改。新构建 Docker 镜像的 API 就绪、最小权限数据库启动检查和 Agent Worker 心跳通过。独立 PostgreSQL 验证旧 schema 与空库升级、最小权限、API 隔离、草稿确认重放、取消后手动完成已发布 Quiz，以及回执清理；容器和卷已清理。真实供应商组合契约验证通过：总结、2 题练习、简答评分及薄弱点出题，17 次模型调用，11,240 Token、15,500 相对成本单位（合成材料，不代表实际资料费用）。
