# 产品需求文档（PRD）

版本：0.1
状态：MVP 基线
产品定位：将用户已有的 PDF、DOCX、PPTX 学习资料转化为可检索、可问答、可练习、可追溯的个人知识空间。

当前实现进度：资料集合、多资料问答与反馈、Quiz、最多 10 份文件的批量上传、扫描 PDF 的中英文 OCR，以及邮箱密码登录与工作区隔离已进入代码。模型语义质量、真实课件评测和公开部署运维仍需单独验收；下列条目同时保留完整产品目标，不表示全部已交付。

## 1. 产品经理视角

### 1.1 用户问题

长篇资料的学习成本主要来自四个环节：定位信息慢、跨资料关联难、理解后缺少验证、复习缺乏针对性。普通聊天式 AI 虽然能快速回答，但若没有稳定的资料范围、引用和生成约束，容易产生无法核验的结论。

本产品的核心价值不是“再做一个聊天框”，而是形成闭环：

```text
导入资料 → 结构化理解 → 有出处的问答 → 按要求出题 → 作答反馈 → 定向复习
```

### 1.2 目标用户

| 用户 | 主要场景 | 最关心的结果 |
| --- | --- | --- |
| 学生与备考者 | 教材、讲义、课件复习 | 快速理解、题目覆盖重点、解析可靠 |
| 知识工作者 | 报告、规范、培训材料 | 跨文档查找、准确引用、节省阅读时间 |
| 教师与培训人员 | 课程资料和练习设计 | 可控地批量出题、检查与复用 |

MVP 优先服务“拥有一批资料，需要自学并自测”的个人用户。团队协作、公开知识库和正式考试不是第一版目标。

### 1.3 产品原则

1. **有据可查**：回答与题目解析应尽可能引用原文位置；无法从资料判断时明确说明。
2. **用户可控**：资料范围、题型、数量、难度、语言和重点可配置。
3. **先读后答**：资料状态未完成索引时，不允许悄悄使用不完整知识库回答。
4. **渐进呈现**：先给结论，再按需展开引用、解释和原文，减少认知负担。
5. **保护资料**：默认私有、最小权限、可删除，并清楚展示处理与保存状态。
6. **不过度承诺**：生成内容是学习辅助，关键结论仍应由用户核对来源。

## 2. 产品范围

### 2.1 MVP 必须具备

#### 资料库

- 上传 PDF、DOCX、PPTX；显示类型、大小、页数、上传时间和处理状态。
- 支持批量上传、失败原因、重新处理和删除。
- 支持资料集合，问答和 Quiz 可限制到一个或多个集合/文档。
- 文件名相同不视为同一文件；使用内容哈希检测真正重复文件。

#### 文档处理

- 提取正文和结构元数据：PDF 页码、DOCX 标题层级、PPTX 幻灯片编号。
- 清洗页眉页脚、空白和明显重复内容，同时保存可追溯的原始位置。
- 文本分块、Embedding、索引；显示排队、解析、索引、完成、失败状态。
- 扫描版 PDF 使用中英文 OCR；无法识别时给出可重试的失败原因。

#### 基于资料的 Agent 问答

- 支持连续对话与资料范围切换。
- 回答包含可点击引用，引用可定位到页码、章节或幻灯片。
- 检索证据不足时返回“不足以从资料得出结论”，而不是自由补全。
- 支持停止生成、重新生成、复制和反馈。

#### Quiz

- 题型：单选、多选、判断、简答。
- 参数：题目数量、难度、题型比例、资料范围、知识点、语言。
- 每题保存答案、解析、引用来源、生成版本和人工编辑状态。
- 客观题即时评分；简答题给参考答案与模型评分提示，并标注非人工评分。
- 完成后给出总分、错题、知识点薄弱项和返回原文的入口。

#### 账号与隐私

- 用户只能访问自己的空间、文档、对话和 Quiz。
- 删除文档后，原文件、解析文本、分块、向量和相关缓存进入可追踪的删除流程。
- 操作失败不得在页面或日志中泄露数据库地址、密钥、模型请求全文等敏感信息。

### 2.2 暂不进入 MVP

- 多人实时协作、公开分享市场、正式考试监考。
- 手写公式的高精度 OCR、复杂表格完全还原、音视频转写。
- 自动训练/微调模型。
- 自主访问互联网或执行任意工具的开放式 Agent。
- 独立微服务、Kubernetes、多区域部署。

## 3. 关键用户流程与验收

### 3.1 上传与索引

1. 用户选择文件并在上传前看到格式、数量和大小限制。
2. 上传成功后立即出现资料卡片，状态为“等待处理”。
3. 后台按“解析 → 分块 → 向量化”推进，并显示当前阶段。
4. 成功后可问答和出题；失败后显示可理解的原因与重试入口。

验收标准：

- 不支持的扩展名、伪造 MIME、超限文件会被服务端拒绝。
- 重复提交和任务重试不会生成重复文档或重复分块。
- 文本型和扫描版 PDF 均可按页查看正文和页码；OCR 无法识别时明确说明。
- 资料库显示真实上传进度和后台处理状态；阅读器支持 15–21px 字号、三档行宽、深浅主题、键盘翻页与可关闭的来源面板。
- 删除后原文件、解析版本和页正文不可再访问；重复删除保持幂等。
- 任一回答引用可定位回原文来源。
- 删除后该文档不再参与新检索。

### 3.2 问答

1. 用户选择资料范围并提问。
2. 系统改写检索问题，执行混合检索与重排，生成带引用回答。
3. 用户展开引用，在侧栏查看原文上下文。

验收标准：

- 页面持续显示当前资料范围。
- 每个事实性核心结论有引用，或回答明确说明证据不足。
- 单个模型/检索调用失败有有限重试，最终失败可恢复且不会重复扣费。
- 用户可对“有帮助/无帮助/引用不准确”进行反馈。

### 3.3 生成与完成 Quiz

1. 用户配置题型、数量、难度和范围。
2. 系统异步生成并做结构校验、答案一致性校验和引用校验。
3. 用户逐题作答，提交后查看成绩和解析。

验收标准：

- 题目数量和题型符合配置；不足时说明实际生成数量。
- 题干不直接泄露答案；选择题选项不重复且答案属于选项。
- 每道题至少有一个资料来源；无法找到来源的题目不进入最终 Quiz。
- 重复提交答案不会生成两份作答记录。

## 4. 状态模型

### 4.1 文档状态

```text
uploaded → queued → parsing → chunking → embedding → ready
               ↘ failed ← 任一步骤
ready/failed → deleting → deleted
```

状态只允许沿定义的方向转换；重试产生新的处理尝试记录，而不是覆盖失败证据。

### 4.2 Quiz 状态

```text
draft → generating → ready → in_progress → submitted
                    ↘ failed
```

## 5. 非功能需求

| 类别 | MVP 目标 |
| --- | --- |
| 可用性 | API 与任务服务具备独立健康检查；外部模型故障不影响资料浏览 |
| 性能 | 普通列表接口 P95 < 300ms；检索阶段 P95 < 1.5s；生成过程采用流式反馈 |
| 大文件 | 上传采用流式写入；解析与索引异步化，不占用 API 请求进程 |
| 安全 | 默认私有、对象级授权、短期下载链接、输入校验、密钥不入库不入日志 |
| 可维护性 | 领域模块隔离，业务逻辑不依赖 FastAPI Request 或具体模型 SDK |
| 可观测性 | 请求、任务、模型调用具有相关 ID；记录耗时、Token、失败类别和检索质量指标 |
| 可访问性 | 键盘可完成主要操作；颜色不是唯一状态表达；支持减少动态效果 |

性能目标必须用接近真实大小的资料做基准测试后校准，不作为未经测量的承诺。

## 6. 核心指标

- 激活：上传后 24 小时内完成至少一次带引用问答或 Quiz。
- 成功：文档处理成功率、引用可定位率、Quiz 结构校验通过率。
- 质量：回答有帮助率、引用准确率、题目有效率、用户删除/重生成率。
- 效率：首个可用回答时间、每份文档索引耗时、单次问答与出题成本。
- 留存：7 天内再次阅读、问答或完成 Quiz 的用户比例。

避免只追求对话次数；本产品真正目标是帮助用户理解和记住资料。

## 7. 迭代路线

| 阶段 | 交付内容 | 完成门槛 |
| --- | --- | --- |
| 0 基础 | 认证、迁移、对象存储、任务队列、日志 | 安全与部署基线通过 |
| 1 资料 | 上传、解析、状态机、删除 | 三类文件端到端可追溯 |
| 2 RAG | 分块、向量/关键词检索、引用问答 | 离线评测集达到质量门槛 |
| 3 Quiz | 可控出题、校验、作答、解析 | 结构与引用校验稳定 |
| 4 体验 | 阅读器、学习记录、弱项复习 | 可用性测试完成 |
| 5 扩展 | Office 图片 OCR、团队空间、多模型策略 | 由实际使用数据决定 |
