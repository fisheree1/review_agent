# CA6000 课件 RAG 评测

> 实现状态更新（2026-09-23）：下文 `NOT_IMPLEMENTED` 是新增学习闭环前的历史评测结果。集合、多资料对话、范围切换与反馈接口现已实现，并通过合成资料的隔离和端到端契约验证；尚未以 CA6000 真实课件重新运行下述三组行为评测，因此不能将旧的 4/4 单资料结果算作新能力的通过率。

这是一个小型、可复跑的诊断集。它先检查当前 API 是否具备多资料、连续对话和反馈接口；对已实现的单资料问答，再通过正常上传、后台索引和提问流程测量用户实际看到的回答与引用。测试源文件始终从本机读取，不加入仓库。

## 选样与运行

`evals/ca6000-rag-v1.json` 选择三个较小且主题互异的材料：模块与包 PDF（9 页）、异常处理 PDF（13 页）、Python Class PPTX（18 张幻灯片）。前三题各自有可人工核对的目标页或幻灯片；第四题询问课件未给出的考试日期，检查证据不足时是否拒答。固定文件 SHA-256、测试集版本和目标位置使后续模型或分块版本之间可比较。

先启动本地 Compose，然后运行无付费调用的预检：

```bash
uv run python -m scripts.evaluate_ca6000_rag
```

确认 `.env` 中的百炼、DeepSeek 密钥和百炼接口地址可用后，执行有界真实评测：

```bash
uv run python -m scripts.evaluate_ca6000_rag --live
```

默认从当前用户的 `NTU/CA6000/课件` 目录读取；资料位于其他位置时传 `--course-dir`。真实模式最多上传 3 份资料并提出 4 个问题。正文和检索问题会经 Worker 发给百炼，相关检索片段和问题会发给 DeepSeek，因此会消耗额度。脚本只删除本次新建的资料；如果上传命中已有资料的内容哈希去重，绝不删除已有资料。若希望检查完成后仍在阅读器中查看新建资料，可加 `--keep-documents`。异常中断后请依据本地报告的 ID 检查是否需要清理。

免费额度或速率限制较紧时，可分批运行，例如 `--live --document modules`（仅 1 份 PDF、2 个问题）。遇到 `PROVIDER_LIMIT` 应等额度恢复后再试；该次结果标为 `INCONCLUSIVE`，不能计入质量通过率。

需要验证较长课件时可加 `--retry-provider-limit`：索引遇到该错误后等待 65 秒，只重试一次，并复用已保存的向量。若额度本身耗尽，仍会报告 `INCONCLUSIVE`，不会无限重试。

终端仅打印能力状态、文件哈希、用例结果和报告位置。包含问题、回答、引用与耗时的详细报告保存在被 Git 忽略的 `evals/local/`，文件权限为 `0600`；不得上传到公开仓库。

## 判定原理与标准

| 维度 | 自动检测 | 首版通过标准 |
| --- | --- | --- |
| 功能可用性 | 读取 OpenAPI，寻找范围、会话、反馈入口 | 缺失明确标为 `NOT_IMPLEMENTED`，不能算通过 |
| 目标来源 | 正面用例至少引用预先核对的目标页/幻灯片 | 3/3；这是“答案引用命中”，不等同于检索 Recall@K |
| 引用完整性 | 每个结论有引用；引用 locator 与 `/content` 一致；摘录是该来源正文的连续子串 | 所有引用 100% 有效 |
| 基本答案事实 | 检查各题少量必需概念或语法片段 | 3/3；只是快速筛查，不能取代人工语义审查 |
| 证据不足 | 未提供考试日期时返回 `insufficient` 且没有事实性结论 | 1/1 |
| 语义支持 | 人工读本地报告，逐条核对“引用是否真正支持结论” | 3/3；若只引用相邻但不相关的句子，判失败 |
| 性能与成本 | 记录每题端到端耗时 | 建立基线；当前 API 不暴露检索排名和 Token/费用，不设虚假的数值门槛 |

自动通过只代表这些确定性条件达标。对一个新模型、Prompt 或分块策略，至少重跑三次并人工复核不同问题类型，不能凭一次流畅回答宣布质量提升。后续扩展到不同篇幅、含代码与图表、相似主题和中英文提问的 15–20 题，再为期望来源命中率设统计门槛。

### 2026-09-23 本地基线（旧 Voyage Embedding）

按资料分批运行的 4 个问题全部通过自动规则：模块 PDF 2/2、异常处理 PDF 1/1、Class PPTX 1/1。三个正面回答的引用分别落在预标注的第 3 页、第 6 页和第 3 张幻灯片；人工核对了引用句与结论。无答案问题返回 `insufficient`。四次提问耗时约 2–4 秒，此数字仅代表这次本地运行，不是 P95。

首次连续索引三份资料时，第三份在 Voyage 索引阶段收到 `PROVIDER_LIMIT`，脚本报告 `INCONCLUSIVE` 并清理测试资料；稍后单独运行该 PPTX 成功。这是切换前的历史基线，不能代表百炼模型的质量或限流表现。多资料、连续对话和反馈仍为 `NOT_IMPLEMENTED`。

### 2026-09-23 百炼 Embedding 评测

切换到百炼 `qwen3.7-text-embedding` 后，合成数据集 `rag-v1` 的 5/5 用例通过，目标来源均排第 1（证据不足题无目标来源）。经用户明确授权，再使用三份 CA6000 私人课件运行 `ca6000-rag-v1`：4/4 自动通过，三道正面题分别引用目标 PDF 第 3 页、PDF 第 6 页、PPTX 第 3 张幻灯片；无资料依据的考试日期题正确拒答。人工核对了三个答案的引文与结论，均有直接支持；Class 题还引用了第 17 张幻灯片，内容正确但与第 3 张的回答略有重复。

## 新增能力的真实资料验收用例

旧版问答接口固定为 `/documents/{document_id}/questions`，当时缺少跨资料引用字段，历史脚本将三项能力报告为 `NOT_IMPLEMENTED`。现在 `/conversations` 与 `/feedback` 接口及解析版本引用已具备，但下列 CA6000 行为题仍待运行；OpenAPI 检测只能标为 `API_PRESENT_NEEDS_BEHAVIOR_TEST`，不能算作通过。

1. **多资料范围**：同时选择模块与 Class，提问必须结合两份资料的比较题。通过标准是回答至少各引用一个所选文档，且每个引用带文档 ID、解析版本和准确 locator；只选择模块时，关于 Class 独有内容的提问必须拒答，异常处理资料的片段不能出现。再用另一 workspace 的资料构造同主题干扰项，要求检索结果、模型上下文与最终引用的越界次数均为 0；非法文档 ID 返回稳定的授权失败，不泄漏标题或正文。
2. **连续对话**：首问指定 Class，追问“它初始化对象时使用哪个方法”。通过标准是追问正确解析指代并引用当前范围内的来源；刷新页面后消息顺序、回答和引用仍可恢复；切换资料范围后追问不得沿用旧范围证据。三类结果都要通过，并检查重复发送同一幂等键不会新增消息。
3. **反馈**：对一条已保存回答分别验证“有帮助 / 无帮助 / 引用不准确”的写入与读取。通过标准是同一用户对同一回答重复提交保持幂等，冲突的幂等键返回明确错误，其他 workspace 不可写入或读取该反馈；聚合统计不得包含资料正文或完整 Prompt。三种反馈类型、重复提交和越权用例都需通过。

设计原则是先做确定性权限、状态与引用契约检查，再运行少量真实模型题目，最后由人工判断“引文是否真的支持结论”。实现这些 API 时，把上述用例接入同一版本化评测集，并分别测量范围泄漏次数（目标 0）、追问成功率、反馈持久化及越权拒绝。检索 Recall@K 应在检索层使用预标注来源计算，不能从最终答案引用反推；端到端耗时和 Token/费用需要采集后建立基线，不能在当前缺少数据时设虚假阈值。完整能力验收要求三组行为用例均通过；当前 4/4 只代表单资料回答与引用质量的小样本结果。
