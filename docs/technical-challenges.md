# 技术难点与验证路径

本文件面向接手开发、评审和上线验收的人，记录哪些问题会直接影响“私有资料 → 有出处的回答 → 可信练习与复习”。依据是当前工作区代码、迁移和现有设计文档；本地存在未提交改动，以下“已实现”只表示代码路径存在，不表示新功能已经部署或经真实资料验收。线上已验证范围以 [部署记录](./deployment-fisher-ai.md)为准。

| 优先级 | 难点 | 主要失败后果 | 当前状态 |
| --- | --- | --- | --- |
| P0 | 检索前的工作区与资料范围隔离 | 私有正文进入其他用户的模型上下文 | 代码有范围约束；每条新入口仍须隔离验证 |
| P0 | 任务重投、外部调用与恢复 | 重复发布、额外计费或任务卡死 | 租约、调用回执与阻塞状态已实现；故障演练仍重要 |
| P0 | 版本化索引与引用生命周期 | 半成品检索、引用错位或删除后残留 | 版本和原子发布已实现；删除/升级路径需持续回归 |
| P1 | PDF 解析与来源定位 | OCR 错字、表格顺序错乱、无法打开引用 | PDF 有解析和原文件预览路径；复杂版式质量待扩样验证 |
| P1 | 答案与题目的语义可靠性 | 引用真实但不支持结论，或无效题被发布 | 结构及来源校验已实现；语义质量需真实资料评测 |
| P1 | 作答保存、评分与继续学习 | 丢失草稿、重复评分、误用其他范围成绩 | 修订保护和事务内恢复已实现；跨刷新与失败需回归 |
| P1 | 兼容部署、性能与备份恢复 | 新旧 Worker 冲突、性能退化、无法恢复数据 | 本地迁移文件已到 `0015`；线上记录为 `0014`，恢复目标未验收 |

## 1. 私有资料必须在检索前限域

**难点。** 对话可选择集合或多份资料，历史消息还保留各自发送时的范围。只在检索结束后过滤答案已经太晚：越界片段可能先进入重排或模型上下文。索引版本变化、删除和跨工作区同名资料会增加漏筛风险。

**当前做法。** [范围展开与检索](../app/learning/scope.py)在 SQL 层约束 workspace、所选文档、活动解析版本及未删除状态；[单资料问答存储](../app/rag/store.py)也按工作区与活动版本查询。[学习闭环](./learning-core.md)规定切换范围仅影响新消息，旧消息保留原范围。

**验收重点。** 用两个工作区、同主题资料和历史范围切换构造干扰项，检查检索结果、模型输入、最终引用都没有越界；跨空间资源 ID 返回稳定的拒绝结果。任何新增查询入口都需补对象级授权与隔离测试。生产是否增加 RLS 第二道防线见[数据库设计](./database-design.md#72-租户隔离)，目前不能把“计划启用 RLS”当作既有保护。

## 2. 至少一次任务与不可确定的外部调用

**难点。** Worker 可能在调用模型后、保存结果前崩溃。数据库只知道请求已发出，不知道供应商是否收费或返回；盲目重试可能重复付费和重复发布。等待用户作答的组合任务还要跨进程重启继续。

**当前做法。** 文档任务使用 PostgreSQL 持久化任务、租约与幂等键，见 [ADR-0001](./adr/0001-postgresql-document-jobs.md)。组合学习通过 [运行处理器](../app/learning/run_application.py)、[运行存储](../app/learning/run_store.py)和 [ADR-0002](./adr/0002-agent-business-checkpoints.md)记录调用序号、状态、结果和累计预算。已保存的返回可回放；租约过期但结果未知时转 `blocked / RUN_RESULT_UNKNOWN`，不自动再次调用。等待输入不占 Worker，阶段成果与下阶段排队在短事务内提交。

**验收重点。** 分别在调用前、调用中、收到返回后、发布前模拟进程中断和重投，确认结果不重复、累计预算不归零、未知结果不被自动补发；检查取消、删除和到期清理。外部供应商是否收费一次无法由本系统保证，需用实际账单校准成本记录。

## 3. 索引原子可见与可追溯引用

**难点。** 文档可重新解析和重新 Embedding；如果新索引分批写入时就可检索，用户会得到部分结果。引用若仅保存“第几页”，版本替换后可能指向另一段文字。删除还要清除派生内容与旧引用副本。

**当前做法。** [文档版本与任务存储](../app/documents/infrastructure/repository.py)管理解析版本和活动版本，[RAG 存储](../app/rag/store.py)只接受就绪索引；引用携带解析版本和内容单元定位。[数据库设计](./database-design.md)说明分块、索引、对话与 Quiz 的工作区约束以及版本删除传播。

**验收重点。** 在索引进行一半时提问，必须仍使用旧的完整版本或得到未就绪结果；重索引后旧引用按指定版本打开；删除后不能通过阅读 API、检索、历史引用或 Quiz 再取回该文档。迁移需同时验证空库和上一版本升级，不能用破坏性 downgrade 作为生产回退。

## 4. PDF 解析与安全边界

**难点。** PDF 按页定位。扫描页依赖 OCR；复杂表格、图片文字和版式可能让提取顺序与人类阅读顺序不一致。上传文件本身不可信。

**当前做法。** [PDF 解析适配器](../app/documents/infrastructure/)输出内容单元与页码 locator；[上传校验](../app/documents/application/upload_validation.py)限制类型和大小，Worker 异步解析。当前支持扫描 PDF 的中英文 OCR；前端只预览原文件，见[产品需求](./product-requirements.md)。

**验收重点。** 用文字 PDF、扫描 PDF、损坏 PDF、超限文件与伪造类型文件检查解析结果、失败码、来源定位与资源上限。解析器的进程级隔离已有设计；更强的独立无网络沙箱仍是[架构文档](./architecture.md#9-安全架构)列出的生产加固项。

## 5. 来源有效不等于结论正确

**难点。** 引文 ID 正确、摘录确实来自原文，只能证明“引用存在”，不能证明“它支持这句话”。多资料比较、近似概念、表格和 OCR 错字更容易出现看似可信的错误。Quiz 还可能出现答案不在选项中、重复题、题干泄露答案或缺少来源。

**当前做法。** [RAG 规则](../app/rag/domain.py)校验答案结构与引用，[练习规则](../app/learning/domain.py)校验候选题；证据不足时拒答或不发布题目。受限 Agent 只可搜索、读取命中来源和生成结果，工具步数与费用受限，见[架构边界](./architecture.md#5-agent-设计边界)。

**验收重点。** 合成评测验证范围、结构、引用及拒答；真实课件再由人工逐条判断引用是否支持结论，并记录来源召回、有效题比例、耗时和费用。[CA6000 评测](./ca6000-rag-evaluation.md)的 4/4 结果仅覆盖小样本单资料问答，多资料连续对话、组合学习及成本门槛仍待单独验收。不能用字符串摘录校验替代语义评审。

## 6. 作答修订、评分与恢复

**难点。** 自动保存可能与提交并发；响应丢失会让客户端不知道值是否已保存。简答题模型评分是外部调用，完成后还要准确唤醒原学习运行。复习必须依据真实提交的成绩和相同资料范围，不能让模型臆造薄弱点。

**当前做法。** `0014_agent_workflows` 增加 `expected_revision`，同值重放可恢复丢失确认，陈旧写入返回冲突；[运行存储](../app/learning/run_store.py)在评分事务内推进关联运行。[学习闭环](./learning-core.md)说明答案隐藏、评分、来源与范围边界。

**验收重点。** 慢网、重复点击、刷新、两个标签页并发作答、提交前仍有保存请求、评分 Worker 重投和取消后的手工完成都应保留用户真实答案，且只产生一次成绩。简答评分须明确标识为模型提示；未提交作答不得驱动错题复习。

## 7. 从本地功能到可恢复的线上版本

**难点。** 新迁移、API、Worker 和前端可能在部署窗口短暂混用。当前本地已有 `0015_learning_organization`，而[线上部署记录](./deployment-fisher-ai.md)仍记录 `0014_agent_workflows`。本地通过测试不能证明线上已有新行为。生产数据同时在 PostgreSQL 与私有对象存储，备份必须成对可恢复。

**当前做法。** [运维手册](./production-operations.md)要求兼容迁移、同版本 API/Worker、功能开关与保留旧运行的回滚路径；[数据库设计](./database-design.md#8-迁移规范)说明迁移原则。线上记录明确尚未启用异机备份或完成恢复演练。

**验收重点。** 使用前一 schema 与空库分别升级，验证旧数据、权限和运行角色；在新旧 Worker 交替时检查待办任务；用接近真实规模的资料测量列表、检索、索引与费用。正式宣称恢复能力前，在隔离环境按生产拓扑完成数据库与对象存储成对恢复，并确定 RPO/RTO。上线操作以实际部署配置和当前备份状态为准。

## 使用这份文档

变更某一难点时，先找到对应代码和用户失败场景，选择能证伪改动的最小测试；跨越数据、任务或权限边界时再扩大验证。将新证据写回相应的产品、架构、数据库或运维文档，并保持本文件的“当前状态”和“验收重点”一致。具体测试选择遵循[开发规范](./development-guide.md)和仓库 `review-agent-pr-check` 技能。
