# 真实 PDF 的 Agent 评测

用自己实际学习的 PDF 建立固定题目、页码和评分标准，再走网站同一条上传 → Worker 解析/OCR → 索引 → 对话 Agent 流程。`scripts/evaluate_pdf_agent.py` 使用 `/conversations` 与图运行接口；旧 `evaluate_ca6000_rag.py` 的单文档严格 RAG 结果不能替代此评测。

## 先建立金标准

1. 固定原文件，记录 SHA-256、物理页数和评测集版本。物理第 1 页从 PDF 封面算起，不使用课件内另印的页码。
2. 人工阅读正文和图表，按知识点选题。推荐包含定义、比较、多页综合、计算、业务应用、图表、追问、整章总结、错误前提和没有资料依据的问题。
3. 为每题标注可接受来源页、参考答案和语义评分要点。来源页按组配置：`[[9,19],[17,19]]` 意味着第一组命中 9 或 19，第二组命中 17 或 19；同一页足以支持两项时允许重复命中。
4. 参考答案和来源不能由受测 Agent 的输出倒推。图表必须看渲染页核对；OCR 能提取文字不代表能保留流程图的连线关系。
5. 允许模型用通用知识补充解释和例子，正确补充不扣分。要求 PDF 中的核心事实和页码准确；未知考试安排等文档特有事实不能编造。

金标准保存在 `evals/local/<dataset>/gold.json`，采用以下结构（示意，不是真实课件答案）：

```json
{
  "schema_version": "pdf-agent-eval-v1",
  "version": "my-course-v1",
  "pdf_sha256": "替换为原文件的64位SHA-256",
  "page_count": 26,
  "cases": [{
    "id": "C01",
    "category": "definition",
    "question": "请解释本课件中的一个核心概念。",
    "expected": "answered",
    "source_page_groups": [[3, 4]],
    "concept_groups": [["标签", "label"]],
    "reference_answer": "人工核对后的参考答案。",
    "rubric": ["区分输入与目标，不混淆真实值与预测值。"],
    "visual_pages": [],
    "setup_question": null
  }]
}
```

`expected=insufficient` 时来源页组为空；`setup_question` 用于同一对话中的先问再追问。`concept_groups` 是中英文同义关键词的初筛条件，参考答案和 rubric 才是人工语义判断标准。空页组、越界页、重复题目 ID 和文件哈希变化会被拒绝。

## 运行

默认仅检查文件和金标准，无模型调用，也不要求 API 在线：

```bash
uv run python -m scripts.evaluate_pdf_agent \
  --manifest evals/local/ca6001-v1/gold.json \
  --pdf '/本机路径/CA6001 Super & Unsupervised Learning.pdf'
```

本地 API、Worker 和模型配置可用后，加 `--live`。真实模式将解析文字发送给已配置的阿里云百炼生成向量，将相关片段发送给 DeepSeek 生成回答，消耗模型额度。一次最多 20 道题；每题有超时，追问有额外一轮，整章总结可能分批生成。可用 `--case C01 --case C07` 缩小本次范围。

```bash
uv run python -m scripts.evaluate_pdf_agent \
  --manifest evals/local/ca6001-v1/gold.json \
  --pdf '/本机路径/CA6001 Super & Unsupervised Learning.pdf' \
  --base-url http://127.0.0.1:8000 --live
```

只连接回环地址，认证来自本机 `.env` 的开发令牌。完整答案、金标准与逐题结果只写入 Git 忽略的 `evals/local/`，报告权限 `0600`，终端不打印课件内容、回答或凭据。原 PDF 不复制进 Git。脚本逐题保存结果，失败也输出已完成部分。默认仅删除本次新建资料及其依赖；命中已有文档的哈希去重时不会删除它。`--keep-document` 可保留新建资料供检查；中断后需按本地报告的文档 ID 检查残留。

## 评分与复核

| 指标 | 含义与限制 |
| --- | --- |
| 知识点结构 | 每个知识点有标题、讲解和引用，适配右侧 PDF 阅读 |
| 引用完整性 | 摘录在对应解析版本正文中，locator 与物理页匹配，文档/版本在选定范围中 |
| 目标页组覆盖 | 最终答案引用了预先标注的目标；不能用它冒充检索 Recall@8 |
| 概念初筛 | 中英文关键词的快速检查；无法检测否定、因果错误或同义改写，应人工复核 |
| 语义质量 | 按 rubric 核对事实、计算、图表连线、引文是否支持核心结论，以及补充解释是否正确 |
| 无依据问题 | 返回 insufficient 且没有编造的事实性结论 |
| 耗时 | 分开记录解析、索引、每题端到端耗时；追问耗时不包含前置轮次 |
| 用量 | 可选读取同一数据库的回执，记录模型/Prompt/图版本、Token、调用次数及内部 cost_units；cost_units 不是货币 |

`--observe-db` 读取当前工作区的运行回执，并在运行中复用已经保存的查询向量重放生产检索 SQL，计算期望页组 Recall@8。发布后生产系统会清空私有回执结果，因此评测只捕获来源 ID、页码和排名等元数据，保存最终用量；前置追问轮次另存 `setup_observation`。必须让 `POSTGRES_HOST/POSTGRES_PORT/POSTGRES_DB` 指向受测 API 的数据库。不会新增向量调用，也不会修改检索策略。报告明确标为 `retrieval_replay`，这是相同索引下的重放结果，不能宣称捕获了原始模型上下文。轮询来不及捕获向量时明确记录缺测，不从最终引用反推 Recall@8。整章总结通过遍历分批读取，不适用 Recall@8，查看图运行 coverage。

### CA6001 首次基线的测量边界

17 题真实基线使用 `study-graph-v4`，原始报告保存在本机私人目录。首次脚本在发布后读取回执，未捕获任何查询向量，因此没有 Recall@8；Token 和调用统计仅覆盖主问题，不含 C16 的前置轮次与文档索引的向量用量。这个结果保留为首次基线。之后补充运行中捕获元数据和前置轮次用量；优化过程中的真实运行已取得部分重放检索元数据，但中途诊断版本不能作为最终改动的通过证据。

### 生成策略变更的对照

v5 的 focused 生成最多 4 点，概览每批仍最多 8 点；使用同范围已编号摘录，服务器填入准确引文，已收到的非法回答最多修复一次。混合图文解析策略另行版本化。最终评测应在冻结代码后运行，记录 `application_sha256`（全部 app Python 源码与相对路径的指纹），不能仅用未提交改动前的 Git HEAD 标识受测实现。

消息与运行状态来自两个独立请求，发布可能在两次读取之间提交。评测读到 completed 运行与 processing 消息时重新读消息，不能误判生成失败，也不能重新提交问题。前置轮次使用相同规则。中途结果和最终版本分别保存，既不覆盖基线，也不从多次试跑中挑最好的题拼成通过率。

OCR 文字位置可补充图表标签，不具备完整箭头拓扑；语义复核要区分正确任务结论、引用支持程度和未完成的图表映射。现有资料哈希去重不会自动重新解析，测试新 OCR 时使用隔离环境中的新解析版本；禁止删改已有学习数据来获得干净评测。

自动结果 `SCREEN_PASS/SCREEN_FAIL` 只代表结构、引用和关键词初筛；人工复核前不称为语义正确率。服务不可用、额度限制、超时或模型响应校验失败为 `INCONCLUSIVE`，单列运行成功率，不能把没有产出回答的用例算成内容质量失败或通过。

第一版先形成一次基线和逐题缺陷清单。后续模型、Prompt、OCR 或分块变更，用同一文件哈希和冻结的题目复跑，最好每版本至少三次，分别比较语义质量、来源覆盖和耗时。不要为提高通过率删除困难图表题或改写金标准去迎合模型。单份 26 页课件不能证明长 PDF、多资料隔离或 Quiz 全部达标；这些能力需要独立评测集。
