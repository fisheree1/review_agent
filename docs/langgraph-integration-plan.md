# LangGraph 与 LangChain 接入规划

日期：2026-09-27。状态：M1–M4 核心能力已实现，生产保持受控开关；M5 的完整真实资料、P95 和货币费用验收尚待完成。持久化方案采用 [ADR-0002](./adr/0002-agent-business-checkpoints.md)，以下原始规划作为设计背景，实际实现以该决策及开发设计的交付记录为准。

用户交互、运行状态、拟新增 API、持久化边界与开发验收细节见 [学习 Agent 工作流开发设计](./agent-workflow-development.md)。本文件说明框架取舍与阶段路线，两者共同说明开发路线与实际交付边界。

## 1. 推荐决策与目标

推荐以 **LangGraph Graph API 编排学习流程，按需使用 LangChain 模型/消息/工具组件**。目标是支持可解释的多步骤任务、等待用户输入、服务重启后的安全恢复和过程展示。

当前项目已有受控工具循环、任务路由、限域检索、引用校验、Quiz 校验和数据库原子发布。接入框架后这些应用规则仍由项目持有；框架负责节点、条件分支、暂停与执行状态。检索质量和题目质量必须单独评测，依赖名称不能代替质量验收。

官方定位：LangChain 提供模型/工具抽象及 `create_agent`；LangGraph 提供可组合确定性步骤与模型决策的底层编排，也可独立使用。依据：[LangChain 概览](https://docs.langchain.com/oss/python/langchain/overview)、[LangGraph 概览](https://docs.langchain.com/oss/python/langgraph/overview)。

| 方案 | 适合的情况 | 本项目取舍 |
| --- | --- | --- |
| LangChain `create_agent` | 以标准模型—工具循环为主 | 可用于隔离实验；已有较多校验/发布/等待作答步骤，不作为主编排入口 |
| LangGraph `StateGraph` | 显式分支、受控循环、暂停与恢复 | 主方案，节点映射现有应用能力 |
| LangChain 模型/工具组件 | 统一模型调用、结构化工具描述 | 保留应用端口，逐个替换适配器 |
| LangSmith | 调试/评测可观测性 | 后续可选；默认不上传私有正文、Prompt 和答案 |

## 2. 第一条产品场景：完整章节学习流程

用户示例：“根据这两份资料总结第三章，再生成 5 道中等难度单选题。我做完后帮我解释错题，再练习薄弱点。”

验收行为：

1. 对话展示结构化任务步骤和本次固定资料范围；参数不清晰时询问缺失信息。明确的任务请求已授权其学习步骤，日常问答/出题不额外增加确认。
2. 生成带来源的章节总结和经校验的 Quiz，展示实际题量与证据不足说明。
3. 等待用户实际作答并提交，释放 Worker 执行资源；刷新页面或重启服务后可继续。
4. 以提交记录为准，展示评分、错题、解析与原文入口；简答评分沿用“模型提示”标记。
5. 使用实际薄弱点生成后续练习；没有薄弱点则结束或提供用户主动发起的新练习建议。
6. 用户可停止剩余步骤；已完成记录保留，未完成内容不发布。

这会扩展当前“一条请求一项任务”的产品边界。实施时同步更新 PRD、任务契约、API 与 UI 文档；新组合任务使用独立的版本化计划 schema，并限制允许的步骤组合。

### 其他应用场景

| 优先级 | 场景与示例 | 使用 LangGraph 的价值 | 结果边界 |
| --- | --- | --- | --- |
| P0 | 完整章节学习：总结 → 练习 → 作答 → 错题复习 | 多步骤编排、跨交互等待、明确状态 | 所有事实结论和题目有有效来源 |
| P1 | 多资料主题研究：“比较两份讲义对概念的解释，列出差异和依据” | 分资料检索、证据汇总、覆盖检查 | 找不到对照依据时说明缺项；不虚构冲突 |
| P1 | 考前复习计划：“根据我的错题制定三次复习任务” | 读取实际记录、生成计划、阶段练习 | 计划为建议；不能编造掌握度，不自动发送提醒 |
| P2 | 教师组卷：“按这份蓝图生成题目，审核后保存题集” | 蓝图检查、候选校验、人工审核暂停 | MVP 保持每份 Quiz 1–10 题；大题集需单独设计配额与分批发布 |

第一阶段服务现有私有学习用户；团队培训、成员共享和公开资源检索需要各自的权限与产品设计。

## 3. 目标技术栈与接入位置

| 组件 | 计划用途 | 引入阶段 |
| --- | --- | --- |
| `langgraph` | StateGraph、条件边、子图、异步执行 | M1 |
| `langchain-core` | 直接使用其消息或工具类型时，显式声明依赖 | M2，按实际使用 |
| `langchain-deepseek` | DeepSeek 模型适配候选 | M2，通过兼容性测试后启用 |
| `langgraph-checkpoint-postgres` | PostgreSQL 异步检查点适配候选 | M3，通过迁移和租户隔离验证后启用 |
| `psycopg` / pool 扩展 | 官方 PostgreSQL 检查点适配需要的独立连接池 | M3，核对直接导入及锁定依赖 |
| LangSmith | 可选的脱敏追踪与评测 | M5，先确定数据外发政策 |

实施时验证 Python 3.13、Pydantic、框架与供应商集成的兼容组合，更新 `pyproject.toml` 和 `uv.lock`，运行依赖审计；本规划不预先宣称某个最新版本组合已兼容。

现有 DeepSeek HTTPX 适配器可被图节点直接调用，因此编排迁移不必同时更换模型调用。`langchain-deepseek` 的结构化输出、工具调用、取消、超时、自动重试和用量字段必须先做契约测试；框架封装不能悄悄绕过调用预算。DashScope Embedding、SQL 检索和现有存储适配器继续作为应用端口使用。依据：[官方 DeepSeek 集成](https://docs.langchain.com/oss/python/integrations/chat/deepseek)。

### 代码职责

- `app/learning/application.py`：业务流程授权、领取/完成任务、确定性结果发布。
- `app/learning/agent.py` 与 `quiz_agent.py`：迁移期间保留当前执行基线和共享预算/校验规则；实现稳定后移除重复编排逻辑。
- 新增 `app/learning/infrastructure/langgraph_workflow.py`：图组装、节点与条件边；应用端口隔离 LangGraph 类型。普通领域类型不导入 LangGraph。
- 新增检查点适配器：仅在 M3 确认隔离和生命周期方案后建立。
- `app/jobs/worker.py`：在 API 请求外运行图；仍由 PostgreSQL 任务租约决定谁有执行权。
- 前端：使用既有学习助手卡片，显示计划、阶段、等待状态和恢复入口；复用作答组件。

### 建议的图

```text
接收请求 → 授权/范围快照 → 规划并校验任务
  ├─ 问答/总结：证据规划 → 搜索/读取循环 → 生成 → 引用校验 → 发布
  ├─ Quiz：蓝图校验 → 证据规划 → 候选生成 → 答案/来源校验 → 发布
  ├─ 复习：读取同范围提交记录 → 展示评分/错题/来源
  └─ 组合学习：总结子图 → Quiz 子图 → 等待提交 → 复习 → 可选薄弱点 Quiz
```

搜索、读取、生成之间用条件边实现真正的工具选择；不能仅在一个图节点里包住旧执行器并宣称完成图编排迁移。初期按顺序执行；只有分资料研究场景测出收益后才增加有界并行，预算按总运行汇总。

## 4. 状态、权限和持久化设计

### 图状态与事实源

运行状态使用有类型的结构：`run_id`、`graph_version`、计划版本/阶段、证据 ID、输出资源 ID、累计预算与截止时间。workspace 与范围由应用绑定的执行上下文提供，模型不能修改；持久化状态中的范围副本恢复时必须和服务器记录核对。

会话、消息、Quiz、作答和评分仍以业务表为事实源。检查点保存执行位置及有限中间状态，不成为第二套答案/成绩/权限库。证据正文只在节点调用时按快照加载；检查点优先保存引用 ID、节点结果引用和计量值。确需保存模型结果时使用私有、限期的运行产物，避免重复请求并明确删除传播。

建议新增业务运行表及阶段执行记录，具体结构在 M3 前评审：

- `agent_runs`：workspace、对话/消息关联、版本、范围快照、状态、当前阶段、累计预算、租约和等待事件。
- `agent_stage_executions`：运行/阶段/尝试的幂等标识、开始/完成/结果未知状态、输出引用和用量。
- 检查点与运行产物：独立适配器拥有的 schema/表，绑定运行；按 workspace 授权访问与清理。

筛选、排序和约束用显式列；可变计划/元数据才使用 JSONB。所有权使用复合外键或等效数据库约束，按真实查询设计索引，不事先固定迁移编号。

### PostgreSQL 检查点接入条件

官方提供 PostgreSQL 检查点和 `AsyncPostgresSaver`，生产持久化不能用进程内存替代。依据：[检查点机制](https://docs.langchain.com/oss/python/langgraph/checkpointers)、[PostgreSQL 示例](https://docs.langchain.com/oss/python/langgraph/add-memory)。

使用标准 saver 前需验证：

1. `thread_id` 由服务端从运行映射生成；它是定位键，不能作为授权凭据。API 不接受客户端指定任意检查点命名空间。
2. 同一对话可有多个运行；图 thread 不直接等同整段 conversation，避免范围切换加载旧执行状态。每次读取、恢复、删除都验证 workspace/运行所有权。
3. 表结构通过 Alembic/部署迁移步骤管理，框架自带建表步骤只能在迁移角色下执行并记录版本；运行角色不得获得建表或 schema 所有权。若 saver 无法满足条件，评估受限包装或定制存储，不能默认放宽权限。
4. asyncpg 业务池与 psycopg 检查点池设独立上限，计算总数据库连接数；任何模型调用不持有事务。
5. 业务提交和检查点写入通常不是同一事务：业务阶段幂等键和输出引用负责对账，检查点缺失时读取已完成结果，不能再生成第二份 Quiz。
6. 删除来源/对话/运行时清除检查点和中间产物，验证备份保留与恢复政策；默认关闭 pickle 等不必要反序列化能力。

### 暂停、恢复与费用

等待用户通过 `interrupt` 表达；恢复使用应用校验后的输入，再映射为框架恢复命令。官方说明恢复会重新执行被中断节点开始处的代码，因此必须分开等待节点和有副作用的节点。依据：[Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)。

- 进入等待时先持久化业务等待状态，退出执行并释放租约；不能占着 Worker 或数据库事务等待作答。
- 提交事件携带服务端确认的 attempt/run/stage 关联；只有实际提交且属于该运行范围的记录才能继续。
- 恢复检查权限、资料版本、取消状态、图版本和累计预算；范围变化需创建新运行或明确重规划，不能静默换资料。
- 重复提交/恢复事件最多推进一次；发布后、写检查点前崩溃也不能重复发布。
- 检查点不保证外部模型请求“只付费一次”。请求已发出但结果未知时，标记该阶段需要处理，禁止自动重发；供应商有可靠幂等接口时才利用它。
- 单阶段初期沿用当前 110 秒和工具上限；长学习流程分阶段执行、等待不计入执行超时。累计预算跨暂停与重启持久化，不能每次恢复重置。组合任务需单独设总阶段数、题集数、总 Token/金额限额并评测后配置。
- 现有宽泛异常处理不能把正常 interrupt 当失败；需在框架适配边界区分等待、失败、取消与恢复。

## 5. 前端与过程可见性

对话内增加“任务计划 / 当前步骤 / 等待作答 / 已完成”展示，支持取消剩余任务和继续。原问答与 Quiz 卡片样式不改变设计系统。

第一版沿用轮询；后续通过已授权 API 将阶段事件转换为 SSE，支持重连后的状态恢复。只发送阶段、资源引用和已校验结果，不暴露图完整状态、Prompt、工具原始参数或未校验答案。图事件可用于生成阶段进度，但浏览器不直接订阅 Worker 内存流。依据：[LangGraph 流式能力](https://docs.langchain.com/oss/python/langgraph/streaming)。

## 6. 分阶段实施与退出条件

| 阶段 | 开发内容 | 完成条件 |
| --- | --- | --- |
| M0 基线 | 补充组合任务、澄清、同范围追问、注入/越权样本；记录当前正确率、P95 时延、费用 | 与旧流程可比较，供应商兼容性假设明确 |
| M1 编排迁移 | LangGraph 接管一条只读问答路径，显式搜索/读取/生成/校验节点；服务端实验开关 | 来源隔离、预算、循环、取消与引用行为等价；无 schema 变更也可先交付 |
| M2 Quiz 与模型组件 | 复用蓝图/来源校验；按需接入 LangChain DeepSeek 适配；固定工具白名单 | 题型/实际题量/答案来源通过；供应商输出和用量契约通过；不重复嵌套两套 Agent 循环 |
| M3 持久化 | 运行/阶段记录、检查点、租约恢复、幂等发布、删除清理、迁移/回退 | 空库/旧库升级；跨空间访问拒绝；崩溃/重复事件/结果未知费用风险验证通过 |
| M4 场景闭环 | 总结 → 出题 → 等待提交 → 评分解析 → 薄弱点练习；统一前端进度 | 一条真实用户旅程跨刷新、暂停与重启可完成；键盘/窄屏/失败状态通过 |
| M5 Beta 评测 | 真实模型 A/B、脱敏指标、费用校准；择机增加研究/复习计划场景 | 质量不低于基线，时延/费用满足预设阈值，具备回滚记录 |

每阶段独立评审、测试和提交。入口由服务端配置选择已固定版本的执行引擎，运行创建后固定引擎/图版本；回滚只影响新运行，等待中的旧运行由兼容 Worker 继续或明确终止。

### 必须覆盖的回归

- 同空间选择范围以内的来源召回、证据不足拒答、引用有效性与实际题量。
- 跨 workspace 访问运行/检查点/恢复接口、伪造提交事件和资料范围扩大均拒绝。
- Worker 在模型返回后、阶段记录后、业务发布后、检查点前分别崩溃；重投结果不重复发布。
- 已取消、已删除来源、旧解析版本、旧图版本、等待超期的运行不能无检查恢复。
- 模型请求结果未知不自动重发；预算在重启和恢复后不会归零。
- 一条组合学习旅程、刷新恢复、键盘操作、390px 布局和错误/澄清状态。

## 7. 开发前准备与建议范围

准备授权评测资料、标准来源/题目标注、模型测试凭据及额度、可接受费用/P95 时延、检查点保留期、目标服务器数据库连接预算。数据外发政策沿用现有模型授权；LangSmith 等额外平台单独确认数据范围。

原实施顺序为 M0–M1 起步：**框架依赖兼容性验证 + 一条 LangGraph 只读问答路径 + 旧/新执行器对比**。M1通过后进入 M2–M4，交付完整章节学习场景。当前规划不承诺框架自动提升回答正确率，也不引入任意执行、开放互联网或多 Agent 协作。
