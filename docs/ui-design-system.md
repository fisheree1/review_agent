# UI 与长时间阅读体验规范

版本：0.4
设计关键词：安静、清晰、可信、专注、轻量。

## 1. 设计目标

界面应把资料、上下文范围和来源放在中心，而不是突出 AI 的“人格感”。用户长时间阅读时，需要较低视觉噪音、舒适行宽、稳定布局和可预测交互；生成和索引过程则用轻量反馈消除等待焦虑。

### 1.1 原则

1. **内容优先**：主内容区域拥有最高视觉层级，操作控件在需要时出现。先用字号、字重、留白和对齐建立层级，再决定是否需要容器。
2. **范围始终明确**：问答与出题页面持续显示当前使用哪些资料。
3. **状态可理解**：上传、解析、生成、失败都说明当前阶段和下一步。
4. **渐进展开**：引用、详细设置、元数据默认折叠，避免一次展示全部信息。
5. **阅读稳定**：流式输出不造成页面横跳；侧栏、段落和滚动位置稳定。
6. **动效有意义**：只解释状态变化和空间关系，不做持续漂浮、闪烁或装饰动画。
7. **容器克制**：资料行用分隔线，辅助区用间距，表单区用排版；仅上传拖放、选中状态、对话菜单和模态框保留明确边界。不把 section 默认做成卡片，也不嵌套多层卡片。

## 2. 信息架构

```text
主导航
├─ 资料库
│  ├─ 全部资料
│  ├─ 集合
│  └─ 上传/处理队列
├─ 学习空间
│  ├─ 阅读与问答
│  └─ 对话历史与分组
├─ 练习（Quiz）
│  ├─ 创建
│  ├─ 待完成
│  └─ 历史与错题
└─ 账号
   ├─ 账户与数据
   └─ 阅读偏好
```

当前桌面主框架使用可收起的左侧导航（展开 200px，较窄桌面 172px；收起后仅显示图标），提供资料库、学习空间、练习与账号入口。收起状态保存在本机浏览器；每个图标仍有可访问名称和悬停标题。内容区使用剩余窗口宽度，高度为 `100dvh`；页面标题与主要操作可见，长列表和消息在所属区域内滚动，长回答行宽仍受限制。

收起按钮与产品名称并排放在侧栏顶部，不单独占用一行；侧栏收起后同一位置显示展开按钮。按钮保持可访问名称，侧栏宽度变化不移动主内容的焦点。

- 资料库：主列展示可扫描的资料列表、筛选与批量管理；窄辅助列依次放置上传、继续学习和学习打卡。辅助内容用间距和细分隔线排列，不做逐块卡片。打卡默认只显示今日操作与统计，展开后才显示月历；保留文件限制、处理阶段和失败信息。
- 学习空间：左侧可收起的对话历史与分组；右侧当前资料范围、对话记录及固定底部输入框。点击“新建对话”立即创建空白会话；可以在对话内选择或调整资料范围，未选择资料时不允许发送。历史对话提供搜索、重命名、移动分组和删除；删除需要确认，失败保留对话和操作入口。资料集合继续作为范围选择入口，不与对话分组混淆。
- 学习打卡：位于首页辅助列，按用户本地时区显示今日打卡、连续天数和累计天数；月历按需展开。只允许为服务器认定的当天打卡，重复点击不会增加次数；切换月份不改变今日状态。
- 练习：左侧历史记录；右侧创建或当前练习。创建页并列组织资料范围与出题参数，生成按钮位于面板底部；语言和实验出题方式收在更多设置中。进入已有练习时不再显示创建表单。
- 阅读页：保留资料导航、PDF 原文件预览和可选问答/引用面板。DOCX/PPTX 展示“暂不支持预览”，不显示后台提取正文。
- PDF 直接按需加载原文件并绘制当前页，页码保存在 URL；提供缩放、加载和重试状态。后台解析排队或失败时仍可预览原文件。

桌面验收以 1440×768 与 1024×768 为基准：上传入口、搜索、对话输入与发送、练习生成按钮完整处于首屏；65 份资料与长消息不会增加整页高度。小于 960px 时主导航使用原生模态框，页面恢复自然滚动；760px 及以下学习与练习以当前任务为先。移动端和 200% 缩放优先可访问性，不压缩内容硬塞进一屏。

## 3. 页面布局

### 3.1 尺寸

- 桌面工作台使用窗口剩余宽度；内容面板通过 `min-width/min-height: 0` 和独立滚动约束尺寸。
- 账号设置用左右两列与一条分隔线；对话分组、重命名与移动弹窗最大 `420px`，其他确认框最大 `560px`，高度不超过 `85dvh`。
- 长回答与引用摘录的理想行宽：中文约 `32–40` 个全角字符，CSS 可用 `max-width: 42rem` 起步并通过可用性测试调整。
- 应用导航 `200px`（较窄桌面 `172px`）；对话/练习历史约 `230px`；阅读器资料导航保留 `240px`。
- 右侧问答/引用面板：当前使用约 `390px`，拖动调整宽度属于后续优化。
- 8px 基础间距系统：4、8、12、16、24、32、48、64。

长回答和引用摘录不使用整屏超宽文本；PDF 预览根据可用宽度缩放，并允许用户调整缩放比例。

### 3.2 阅读与问答布局

```text
┌──────────┬──────────────────────────────┬──────────────────┐
│ 导航     │ PDF 预览 / 不支持提示         │ 问答 / 引用摘录   │
│          │                              │                  │
│ 资料列表 │ 标题、原始页面、页码          │ 提问、回答、引用   │
│          │ 保持独立滚动位置              │ 独立滚动         │
└──────────┴──────────────────────────────┴──────────────────┘
```

引用点击后先在右侧展示已保存的引用摘录，不强制改变当前页。选择“在原文中打开”后，PDF 跳到原始页；DOCX/PPTX 仍显示不支持预览。收起问答可返回打开前的位置。

## 4. 字体与排版

### 4.1 字体栈

优先使用系统字体，减少加载和跨语言渲染问题：

```css
--font-sans: Inter, ui-sans-serif, -apple-system, BlinkMacSystemFont,
  "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif;
--font-mono: "SFMono-Regular", Consolas, "Liberation Mono", monospace;
```

正文不要使用过细字重。中文长文默认：

- 正文 `17px / 1.8`，字重 400。
- 辅助文字 `14px / 1.55`。
- 工作台 H1 `23px / 1.35`、面板标题 `16–18px`；长文阅读标题保留原有层级。
- 段落间距约 `0.8–1em`；列表项间保留呼吸感。

PDF 预览提供独立缩放，界面主题保存在本机。浏览器缩放到 200% 时回答与操作仍可用。

## 5. 色彩系统

采用低饱和中性色作为大面积背景，使用克制的灰蓝色表达主操作与引用。工作区使用开放的白色或深色表面，辅助导航使用轻微对比；层级主要来自排版与留白，不靠连续的灰色底板和描边框。

## 6. 组件规范

### 6.1 按钮

- Primary 每个可视区域原则上只有一个，表示明确的下一步。
- Secondary 用于并列但非主要操作；Tertiary 用于工具型操作。
- 危险操作使用文字明确的按钮，例如“删除资料”，不只放垃圾桶图标。
- 异步提交后按钮进入 loading 且防止重复提交；长任务跳转到可追踪状态，而不是无限转圈。

### 6.2 资料列表

默认优先列表视图，便于大量资料扫描。每行展示名称、类型、集合、处理状态、页数/大小和更新时间；次要操作进入菜单。

处理状态使用“图标 + 文案 + 进度阶段”。失败状态直接提供查看原因和重试，不使用只有红点的模糊提示。

### 6.3 问答消息

- 回答以正常文章排版呈现，不使用大面积聊天气泡。
- 用户问题可用轻微底色区分，宽度仍保持阅读舒适。
- 引用采用紧凑编号标记，键盘可聚焦，悬停/聚焦显示来源摘要。
- 流式输出按段落稳定追加；不要让光标持续闪烁或自动滚动抢夺用户位置。
- 生成中提供“停止”；完成后提供复制、重新生成和反馈。

### 6.4 Quiz

- 创建时默认“标准出题”，可选择“自主规划出题（实验）”；说明该模式按知识点选择检索与阅读步骤，可能耗时更长。历史 Quiz 显示所用方式，实验功能不默认开启。

- 每屏聚焦一个主要任务，可逐题作答，也可在侧栏查看进度。
- 选项点击区域至少 44px 高，选中状态同时有边框、背景、图标。
- 提交前显示未答数量；提交后答案、解析、来源分层展示。
- 正确/错误不能只用绿/红，必须加图标和文字。

### 6.5 空、加载、错误状态

- 空状态说明价值和下一步，如“上传第一份资料，开始带引用问答”。
- 骨架屏仅用于结构已知且短暂的加载；长任务显示阶段、可离开提示和后台通知。
- 错误文案结构：发生了什么、是否影响数据、用户现在能做什么、必要时提供错误编号。

### 6.6 选择菜单与轻量弹窗

- 资料筛选、练习参数和对话分组选择使用同一项目菜单：控件本身展示当前值，展开项用轻微悬停底色和选中标记，不依赖操作系统默认菜单外观。弹层是短暂的交互实体，可使用一层细边框与轻阴影。
- 菜单支持 Enter/Space 打开、方向键与 Home/End 移动、Enter 选择、Esc 返回触发按钮；点击外部或按 Tab 离开时关闭。长选项列表有高度上限，不遮挡视口边缘。
- 新建、命名、移动与删除对话使用窄型对话框；标题、单一字段与右对齐操作按自然阅读顺序排列。取消是低权重操作，保存或确认删除是明确的末尾动作。

## 7. 动效规范

动效用于反馈、层级和空间连续性：

| 场景 | 时长 | 建议 |
| --- | --- | --- |
| hover / press | 100–140ms | 颜色、阴影小幅变化 |
| tooltip / popover | 140–180ms | 淡入 + 2–4px 位移 |
| 侧栏 / sheet | 200–260ms | ease-out 进入，ease-in 退出 |
| 列表新增/状态变化 | 180–240ms | 淡入，高亮一次后稳定 |
| 页面切换 | 160–220ms | 轻微淡入，不做大幅滑动 |

已实现的轻量动效：页面 / 结果淡入、资料列表最多 60ms 的顺序延迟、按钮按压反馈、原生对话框和表单展开、任务阶段一次性淡入，以及作答进度条的平滑填充。进入动效为 180–220ms，交互反馈为 120–160ms；动效只改变透明度或位移；悬停颜色 / 阴影即时更新，不动画化布局高度。正文阅读区保持稳定；点击与键盘操作不等待动效结束。

新增动效只在 `prefers-reduced-motion: no-preference` 下启用。减少动态效果时，页面 / 弹窗 / 结果直接出现，答题进度即时更新，保留选中、聚焦和状态文字反馈。无需增加动画依赖或额外状态存储。

禁止：持续呼吸动画、阅读区视差、长时间闪烁、无意义 loading 动画、生成文本逐字弹跳。

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    scroll-behavior: auto !important;
    transition-duration: 0.01ms !important;
  }
}
```

## 8. 无障碍与键盘体验

- 目标达到 WCAG AA；设计和开发阶段持续自动检查并辅以键盘/读屏人工测试。
- 所有交互元素可通过键盘访问，焦点顺序符合视觉顺序，焦点环清晰可见。
- Modal/Drawer 打开时管理焦点，关闭后归还触发元素；Esc 可关闭非破坏性浮层。
- 图标按钮有可访问名称；装饰图标对读屏隐藏。
- Toast 不承担唯一错误信息；表单错误与字段关联并提供汇总。
- 流式回答使用谨慎的 live region，避免读屏器逐 token 播报。
- 快捷键不得覆盖浏览器/辅助技术常用键，并提供可发现的快捷键帮助。

## 9. 响应式策略

- `< 960px`：主框架单栏；导航使用临时对话框，问答和引用使用临时抽屉；底部操作避免遮挡系统区域。
- `960–1099px`：可折叠侧栏；正文 + 临时问答/引用面板。
- `≥ 1100px`：三栏阅读布局；问答或引用面板可常驻。
- 表格在小屏转换为信息卡或保留关键列，不能简单缩到不可读。

## 10. 当前实现基线

- 学习助手统一“发送任务或问题”输入框，始终展示当前资料范围；点击新建对话直接进入空白会话，范围选择在会话内呈现并保留键盘操作。总结/比较、出题、错题复习、薄弱点练习建议仅填写草稿。Ctrl/Command + Enter 发送，中文输入合成期间不触发；运行中禁用重叠发送并提供停止入口。
- 请求、引用回答、练习和复习使用现有字体、色彩、圆角、边框与间距变量。对话内和独立 Quiz 页面共享作答/成绩/解析组件，提交前隐藏答案和来源。多处显示同一练习时控件与定位 ID 仍唯一；加载、失败、无成绩和无薄弱点都有明确说明。390px 单栏不横向溢出，任务状态以简短状态区播报，避免读屏重复播报整段历史。

- 阅读页的单资料问答使用独立右侧栏，与引用摘录共用右栏并分别滚动；长回答不会挤动预览。打开问答时记录页码和阅读位置，收起时恢复；窄屏侧栏作为可用 Esc 关闭的临时面板。引用按钮先显示已保存的摘录，选择“在原文中打开”后 PDF 定位到对应页。
- 回答在引用校验完成后整体呈现；支持停止、复制回答与引用、失败后重新提问和最近 20 条记录。首版不展示未验证的流式文本；无证据时说明不足，不显示伪引用。

- 资料库采用左右工作面板与紧凑文件列表，展示真实上传进度、解析阶段、页数、大小和可解释失败。
- 阅读器桌面端采用 `240px / PDF 预览 / 390px` 三栏；窄屏将导航与问答/引用转换为临时面板。
- PDF 原文件按需下载一次，PDF.js 只绘制当前页；页面数从原文件获得，缩放由预览工具栏控制。
- `[`、`]` 逐页导航，`?` 打开快捷键说明，`Esc` 关闭临时面板。所有图标按钮提供可访问名称。
- 上传期间禁用重复选择并允许取消；上传成功后进入可恢复的处理页，处理状态由服务端数据轮询更新，PDF 可以立即预览。
- 删除使用明确的不可恢复确认对话框；移动端导航和引用面板打开后转移焦点、限制焦点范围，并可用 `Esc` 返回原操作位置。

不要只按设备名设计；用内容在断点处是否拥挤作为判断依据。

## 11. 文案规范

- 使用用户语言：“资料处理中”，不显示“embedding pipeline running”。
- 按钮使用动词：“生成练习”“重新处理”“查看引用”。
- AI 不确定时直说：“在所选资料中没有找到足够依据”。
- 删除确认说明影响范围和可恢复性，避免笼统的“你确定吗”。
- 同一概念只用一个名称：界面统一使用“资料”“集合”“练习”“引用”；开发文档中的 Quiz 指练习领域。

## 12. 设计验收清单

- 主任务在 5 秒内可被首次使用者识别。
- 所有页面包含 loading、empty、error、disabled 和 success 状态。
- 资料范围与处理状态在关键流程始终可见。
- PDF 页面缩放、翻页和长时间预览保持可用，引用摘录保持舒适行宽。
- 浅色、深色、高缩放、键盘和减少动态效果模式均通过检查。
- 动效不造成布局位移，不延迟用户操作，不影响读取。
- 引用可追溯、可键盘访问，并保持用户原来的阅读位置。

### 轻量学习辅助

- 首页“继续学习”最多展示两个入口：进行中的任务或最近对话，以及未完成作答。没有记录时隐藏；加载失败可就地重试，不增加独立仪表盘。
- 对话记录独立滚动。停留在末尾时跟随新消息；阅读历史或操作消息内控件时保留位置，由“有新回复”按钮返回末尾。手机输入框紧接记录并预留系统安全区域，保持正常布局，避免矮屏上的吸附输入框遮住消息。
- 对话回答和提交后的 Quiz 来源共用折叠引用摘录，直接展示已保存的引文，不向前端读取整页提取正文；保留“查看原文”入口。PDF 跳转原始页，DOCX/PPTX 显示不支持预览。
- Quiz 用紧凑题号导航标记已答、未答和建议复习；可只看未答题或薄弱题。未答筛选保留开启时的题目集合，填写答案不会立刻移除正在操作的题；题号跳转会清除筛选并将键盘焦点移到目标题。
- 失败信息贴近对应操作；保留输入、选择和未保存作答，重试不清空页面。首次空资料库显示上传说明和上传入口。
