# ADR-0005：对话只经由持久运行，阅读页问答共用执行核心

- 状态：Accepted
- 日期：2026-10-11
- 范围：对话消息的执行路径、阅读页单资料问答的生成方式。

## 背景

对话消息有两条执行路径：`AGENT_GRAPH_ENABLED=false`（生产 Compose 默认值）时由 `LearningProcessor.process_message` 直接处理，开启时创建 `agent_runs` 由 `AgentRunProcessor` 处理。两条路径各有一套领取、租约、取消、出题预留和结果发布代码，行为逐渐分叉。阅读页问答由 `RagProcessor` 自带一套检索加 `cited-claims-v1` 生成，与对话的逐点讲解和修复逻辑不同。

## 决策

- 删除开关和消息直接处理路径：`ask` 总是创建运行。迁移 `0019` 把仍在排队或处理中、没有运行的旧消息交给 `study-graph-v5` 运行，从规划开始；降级只撤回尚未开始的迁移运行。
- 阅读页问答保留 `rag_questions` 表和 API，执行改为注入的 `QuestionAnswerer`。Worker 组装时传入 `reader_answerer`，即与对话相同的 `answer_focused`（一次检索、一次生成、逐点校验、最多修复一次）。`rag` 只定义端口，不依赖 `learning`。
- 回答响应增加可选的 `title`/`explanation`，历史回答仍可读取；对话与阅读页共用同一个回答模型。
- 不把阅读页问答和独立出题并入 `agent_runs`：那需要可空的对话外键、归属列和兼容层，收益主要是存储层统一，而执行核心已经统一。

## 影响

- 每条对话都有持久运行，享受调用回执、预算、取消与恢复；生产正式启用工作流。处理中的旧消息若已发出模型请求，迁移后从规划重跑，可能再计费一次。
- 部署前必须停止旧 Worker，否则旧 Worker 仍会直接处理消息。
- 阅读页回答变为逐点讲解格式，前端显示每点标题和讲解；质量需用真实资料评测确认。
