# ADR-0004：领域状态机、两版本保留策略与按实测计时

- 状态：Accepted
- 日期：2026-10-11
- 范围：学习运行的阶段流转、可执行图版本和执行时间预算。

## 背景

阶段流转写在 `SqlAgentRunStore` 的六个方法里，每处都按 `graph_version` 分支判断下一步；`AgentRunProcessor` 用一条长条件链分派阶段。v1–v5 五个版本同时可执行，代码中有 30 多处版本判断，测试和冒烟脚本随新版本不断过期。计时方面，每次领取固定预留 110 秒并永久计入，PDF 等无模型阶段也占用同样预算，长 PDF 概览因此需要 1,540 秒上限。

生产 `main` 只创建过 `study-graph-v1` 运行；v2–v4 只出现在未合并的开发分支。

## 决策

- 转移规则移入纯领域模块 `app/learning/run_flow.py`。旧 v1 的任务动作映射为组合步骤，两类运行共用一张转移表，并用表驱动单元测试固定行为。存储只负责持久化，在同一事务内写入成果和下一阶段。
- `AgentRunProcessor` 按阶段查表分派处理器。
- 只保留“生产在用版本 + 当前版本”：v1 和 v5。其他版本在领取时关闭为 `RUN_VERSION_UNSUPPORTED`，处理器也拒绝执行。
- 领取时按阶段类型预留时间（模型阶段 110 秒，PDF/复习 15 秒），阶段结束后用实测耗时替换预留，崩溃时预留保留。

## 影响

- 运行流转可以不连数据库直接单测；新增阶段类型只需加一条规则和一个处理器。
- 开发数据库中残留的 v2–v4 运行会被关闭，需要重新提问。生产不受影响。
- 时间预算反映实际耗时，同样的上限能容纳更多实际工作；崩溃情况下仍偏保守。
- 发布 v6 时：先部署能执行 v1、v5、v6 的 Worker，再启用创建 v6 的 API；v5 在途运行结束或到期后，下一次发布再移除 v5 路径。
