# 资料范围内自主规划 Agent：开发计划

## 目标与边界

第一阶段让多资料连续问答由模型选择下一步：搜索当前资料、读取已命中的来源，或提交带引用的回答。用户选择的 workspace、资料集合和解析版本始终由应用持有；模型只得到允许列表中的工具名称和受限参数。Agent 不访问互联网、文件系统、SQL、删除或分享接口，也不自行扩大资料范围。

多资料问答是第一条只读纵向切片。第二阶段增加显式选择的实验 Quiz Agent：模型选择搜索、读取已命中的来源和生成候选题；应用校验后原子发布。第三阶段统一对话入口，让用户通过自然语言选择问答、练习和复习。单资料旧接口和默认独立 Quiz 生成沿用固定流水线；前端继续使用既有异步任务状态和引用定位。

## 开发顺序

1. **工具契约**：定义版本化的结构化决策，以及 `search`、`read_source`、`answer` 三种动作。搜索词有长度上限；来源 ID 只能来自本次限域搜索结果。无效工具或参数以稳定错误结束。
2. **执行与预算**：Worker 在短事务外调用模型；每次模型决策后检查请求数、计费 Token 与相对费用单位，同时限制工具步骤、重复搜索/读取和整条任务时长。预算耗尽不发布未经校验的回答。
3. **证据与发布**：搜索复用现有 workspace、选中资料、当前解析版本和删除状态过滤；只有已读取的来源能进入最终回答模型，随后沿用引用 ID、原文摘录与租约校验。
4. **验收**：用假模型覆盖多次工具选择、无证据拒答、越权来源 ID、重复循环、超预算、取消和无效输出；在隔离数据库运行学习流程，再对版本化合成集与真实资料做语义评测。

## 后续阶段与准备事项

- **质量基线**：`evals/agent-v1.json` 已提供 20 个合成样本，覆盖多资料比较、追问指代、相似干扰资料、证据不足和提示注入。`scripts.evaluate_agent` 默认仅验证数据集；显式 `--live` 才调用付费模型，比较固定流程与 Agent 的预期来源召回、引用覆盖、拒答、注入标记、时延和生成 Token。评测检索器是内存中的限域余弦检索，不代表生产 PostgreSQL 混合召回或引用语义支持率；生产权限由独立数据库联调验证。仍需授权真实资料和人工语义复核。
- **成本控制**：第一阶段用计费 Token 和加权费用单位限额，连同模型请求次数限制单次运行；上线前按实际供应商账单校准单价、全局日预算和告警。相对费用单位不是美元金额。
- **Quiz Agent**：已实现可选实验入口，工具为 `search`、`read_source`、`generate_quiz`。沿用问答执行器的步骤与费用上限，未读来源、无答案及无效候选题不能发布。实际模型质量门槛稳定后再考虑默认启用、扩展知识点覆盖及有限候选修复。
- **写操作**：保存草稿、修改 Quiz 或其他会改变用户数据的工具必须另设授权与审计设计；删除和分享继续由明确用户操作触发。

发布条件：限域与取消测试通过；所有事实性回答都有可定位引用或明确证据不足；预算和工具次数可审计；与固定流水线相比的真实资料质量、时延和成本有记录。真实模型结果未达到这些条件前，不宣称已完成生产质量验收。

## 本次实现与验收记录

第一阶段的工具契约、模型规划适配器和 Worker 执行循环已接入多资料对话。最多 5 个决策、6 次生成模型请求、2 次搜索、3 次来源读取；总生成模型计费 Token 上限为 18,000，加权费用单位上限为 30,000，消息执行超时沿用 110 秒。向量化请求由搜索次数单独约束，未计入生成模型费用单位。成功消息保存版本、累计用量和不包含正文或查询词的工具轨迹；失败沿用稳定错误码，不自动重试结果未知的付费请求。当前无需新增依赖或数据库迁移。

已通过本地单元测试、类型及格式检查和隔离 PostgreSQL/Redis 学习流程联调。联调覆盖集合、多资料检索、范围切换、取消、跨空间与历史版本引用，以及既有 Quiz 流程。隔离容器和数据卷在验收后删除。使用的是合成资料与假模型；真实模型的规划成功率、引用语义支持率、时延与供应商账单对照仍属于上线前准备事项。

上线前需要项目负责人准备：授权评测资料与标准来源标注、测试环境模型凭据及调用额度、单次和每日可接受费用、质量基线及发布阈值。开发过程中不把真实资料、凭据或模型请求全文提交到仓库。

## 第二阶段：实验 Quiz Agent 与评测准备

- Quiz 创建界面新增“出题方式”，默认标准出题；选择“自主规划出题（实验）”发送 `config.generation_mode = "agent"`。省略或传入 `standard` 与历史配置保持等价，旧幂等请求不会因此冲突。非法模式返回 422，同一请求标识切换模式返回 409。
- 模型不能改写出题蓝图，也不能选择保存、发布或评分工具。只读搜索仍在 SQL 内执行 workspace、选中资料、当前版本和删除状态过滤。候选题只能引用已读取的来源，并经既有题型、答案、重复及引文校验；证据不足返回失败，不生成自由知识题。
- 问答与 Quiz 在每次规划前、规划返回后和最终生成前检查任务租约与资料有效性。取消、删除或租约失效后不启动下一次模型或向量调用；已经发出的请求可能无法撤回。发布仍受租约保护。
- `0012_quiz_agent_usage` 为 Quiz 增加可空 `generation_usage` JSONB，成功时与题目同事务保存模型版本、用量和不含正文的工具轨迹。旧记录保持为空。字段不进入公共 Quiz 响应，避免作答前泄露来源；随 Quiz 级联删除，无独立状态库。

### 开发与上线操作

本地无付费验证：`uv run python -m scripts.evaluate_agent`。获得测试环境凭据和调用额度后，可运行 `uv run python -m scripts.evaluate_agent --live --output /tmp/agent-comparison.json`；只评估仓库合成资料，报告不包含回答全文。自动化指标通过仍需人工检查引文是否支持结论。

第二阶段部署先迁移至 `0012`；包含第三阶段的当前部署先执行 `database-init` 升级至 `0013`，再更新 API/Worker 和前端。可空新增列兼容旧进程，不需要回填。回退应用时保留新增列与审计记录；先停止创建新任务并等待在途任务结束。迁移的 downgrade 会移除任务结果和审计列，应只用于隔离环境，生产回退优先保留兼容结构。

隔离空库执行常规迁移；独立的第二个空库执行 `python -m scripts.verify_quiz_agent_migration --isolated`，验证从 `0012` 的已有 Quiz/消息升级并保留数据（可显式 `--previous-revision 0011_version_purge_trigger`）。该脚本拒绝已初始化数据库。之后运行 `scripts.verify_learning_flow` 验证实验模式、模式幂等、跨空间拒绝与私有审计。全局每日真实金额限额、费用告警、真实模型评测和人工语义复核仍待上线准备完成。

## 第三阶段：统一对话任务与一致的前端

### 实施顺序与验收行为

1. **明确任务契约**：版本化任务规划器接受当前请求和同范围最近消息，选择 `answer`、`create_quiz`、`review_mistakes`、`practice_weak_topics` 或 `clarify`。Quiz 蓝图严格限制 1–10 题、题型、难度、主题和语言；模型不能传入工具外操作或资源 ID。一次执行一项任务，含糊和不支持的请求需澄清。
2. **复用执行与发布**：问答/出题各用原证据执行器，任务规划和后续生成共享总预算：最多 7 次模型调用、5 次证据规划、2 次搜索、3 次读取、18,000 计费 Token、30,000 加权费用单位、110 秒。Quiz 通过校验后与消息结果同事务发布，取消不产生孤立 Quiz；每小时 20 次出题在 SQL 内统一计算独立 Quiz 和正在处理的对话预留。
3. **提供可信复习**：应用只选择精确同范围最近提交的作答；实际评分、解析、来源由原 Quiz 流程提供。薄弱点使用真实已提交记录，不能由模型发明。没有记录或没有薄弱点则提示，不启动出题生成。
4. **完成对话体验**：一个输入框同时支持资料总结/比较、带引用问答、可控出题、错题解析和薄弱点练习。对话中直接作答、提交、看成绩、返回原文；复用独立 Quiz 的作答组件和现有视觉变量。当前范围清晰可见，键盘可发送/停止，建议仅填草稿，加载/错误/无记录明确提示。
5. **验证与发布**：聚焦单元测试验证任务限制、共享预算、真实薄弱点和取消；浏览器覆盖同对话完整闭环与 390px 布局；隔离 PostgreSQL/Redis 检查幂等、跨空间复合外键、原子发布、共用配额、空库升级和上一版本保留数据。部署先升级 `0013`，回退保留新列。

这是限于当前资料和学习流程的 Agent。真实供应商的自然语言任务识别率、题目语义质量与账单校准仍需测试环境评测，不能用假模型联调代替生产质量验收。

第三阶段验收：97 项后端测试、14 项前端测试、4 条浏览器流程通过（另 1 条依赖独立环境的流程跳过）。统一对话流程覆盖作答前答案隐藏、评分/解析/来源、薄弱点草稿与发送、键盘和 390px 布局；Ruff、mypy、前端构建、Compose 配置与本地文档链接检查通过。隔离空库升级与 `0012` 既有 Quiz/消息升级均通过，Alembic 元数据一致，完整学习联调通过，容器与独立数据卷已清理。20 条评测样本仅通过结构验证，本轮未调用付费模型。

第二阶段验收：89 项后端测试、11 项前端测试、Quiz Agent 浏览器旅程（包含键盘提交和 390px 窄屏）通过；Ruff、mypy、前端类型检查与构建、Compose 配置和本地文档链接检查通过。空库迁移与 `0011` 既有 Quiz 升级均通过，Alembic 元数据无漂移；两种数据库路径都通过学习流程联调。20 条合成样本的结构验证通过，但尚未运行 `--live`，这些结果不代表真实模型质量达标。
