# Security policy

## Reporting

Do not open a public issue for suspected data exposure, authentication bypass, prompt/tool escalation, credential leakage, or destructive behavior. Once the GitHub remote is configured, use the repository's private security advisory channel.

Until a private reporting contact is configured, stop testing after obtaining the minimum safe evidence and notify the repository owner directly. Do not include real documents, credentials, personal data, full prompts, or database contents in a report.

## Scope priorities

Highest priority areas are workspace isolation, document/object authorization, upload parsing, secret handling, model tool permissions, prompt injection boundaries, deletion completeness, and database backup/recovery.
